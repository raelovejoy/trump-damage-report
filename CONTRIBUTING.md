# Contributing

This repository uses a simple collaboration baseline intended to keep changes understandable, maintainable, and documented without unnecessary process.

## Start from the repository

Treat the repository's current files as the authoritative source for its implementation, documentation, status, and project-specific rules.

Before making a consequential change, read the relevant entry points such as the root `README.md`, status/roadmap documents, architecture notes, and decision records where they exist.

## Documentation coherence

When a canonical idea, capability, architecture, workflow, or project relationship changes, check whether the change should propagate to the documents that help people discover and correctly understand it.

As applicable, check:

- the nearest README/index;
- the root README;
- current-state/status documentation;
- roadmap/planning documentation;
- architecture or decision records;
- cross-project/ecosystem references.

Do not update files mechanically or repeat the same explanation everywhere. The goal is **coherence without duplication**: important changes should be discoverable from the right entry points, while detailed material remains canonical in the most appropriate place.

## Pull requests

A pull request should make it possible to understand:

1. what changed;
2. why it changed;
3. what was tested or verified;
4. what documentation was checked or updated;
5. what remains unresolved, if anything.

Prefer links to canonical material over copied text that will drift.
